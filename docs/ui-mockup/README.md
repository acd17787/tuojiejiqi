## 落地状态（第 1～5 节已实现）

样式层的 1～5 节已经改完并通过离屏渲染验证，第 6 节的「从历史记录添加」按钮和提示词
预设 chip 按约定留到下一轮。落地时额外发现并修掉了一个长期存在的问题，见下。

### 顺手修掉的「按钮全是直角」根因

原来的 `FlatButtonTemplate` / `IconButtonTemplate` / `SegmentButtonTemplate` 都靠
`CornerRadius="{TemplateBinding Tag}"` 传圆角，但 **`Tag` 是 `object`，`TemplateBinding`
不会把它转换成 `CornerRadius`**，结果是静默变成 0 —— 也就是直角。用像素量过改动前的截图：
「导入模型」「涂抹修改」按钮的圆角都是 **0px**，而卡片、预览区、参考图缩略图因为写死了
10/12 反而是圆的。这正是「模型设置那排是方的、别处是圆的」的来源。

修法是换成完整绑定（`{Binding Tag, RelativeSource={RelativeSource TemplatedParent}}`），
5 处模板全部改掉。改完实测：4K 档位圆角 12px、标准模式 12px、头部按钮 12px。

另外提示词输入框和设置弹层的输入框用的是 WPF 默认 `TextBox` 模板（直角），
新增了 `RoundedTextBoxTemplate` 统一成 14/12。

  之前界面上从来没显示过。

### 第四轮：模型设置卡片压缩

原布局三行都是「标签独占一行 + chip 另起一行」，而三行右侧全是空白。上面两行
「图片尺寸 / 图片比例」的标签行合计占 51px，纯属浪费。

改成：

- **标签内联**：`图片尺寸 [1K][2K][4K]`、`图片比例 [原图][1:1]…`，标签占左侧固定 66px 列，
  两行标签因此左对齐。省掉两整行。
- **状态读数上移到标题行**：`模型设置` 右边原本整片空白，现在放
  `按原图 1:1 · 输出 3520 × 2336 · 8.2MP`。其中 `AutoRatioHint` 只在选中「原图」时有值，
  其余时候是空字符串，平时不占位置。
- 标题行下边距 13 → 10。

宽度安全性：比例 chip 实测每个 48px + 6px 间距 = 一行 324px，加 66px 标签列共 390px；
两栏布局最窄（窗口 1121）时卡片内容区约 458px，不会换行。

**实测：模型设置卡片 260px → 226px（−34px，−13%），整窗 960px → 931px。**
同一行的「参考图像」卡片跟着变矮，底部空白同步减少。

顺带发现 `RenderSettings.RatioSummary`（= `AutoRatioHint`）全项目无人引用，是死代码。

**还能再压但没做的**（怕显得挤）：模式按钮 40 → 34（−6）、尺寸/比例 chip 34/32 → 30（−6）、
卡片上下内边距 15/17 → 13/14（−5），合计再省约 17px。

### 第五轮：历史抽屉（塞 15 张图实测）

`history-drawer.png` 是用 15 张不同长宽比（1:1 / 3:2 / 16:9 / 竖构图）的合成图渲染的实测图，
看出两个真实缺陷：

1. **左右不对称**：左边距 12px、右边距 21px。`UniformGrid Columns="2"` 的每个 item 只写了
   右边距（`Margin="0,0,10,10"`），最后一列右侧永远空 10px。→ 改 `Margin="5,0,5,10"`，
   ItemsControl 边距 12 → 7，现在左右都是 13px。
2. **缩略图方角盖在卡片圆角外面**：`ClipToBounds` 只裁矩形不裁圆角，而 `UniformToFill` 是铺满的，
   图片直角直接压在卡片 12px 圆角上。→ 把 `Image` 换成 `ImageBrush` 当 Border 的 Background，
   Border 的圆角就能裁到画刷本身。**参考图缩略图有同样的毛病**（`CornerRadius=14 + ClipToBounds`），
   一并改了，并用真实 PNG 文件验证过。
3. 改 ImageBrush 的副作用：图片不再有固有尺寸，抽屉会按内容收缩（368 → 284）。
   把 `MaxWidth="368"` 改成 `Width="368"`（窗口 `MinWidth=720`，368 永远放得下）。

### 第六轮：把 30 条上限摆到界面上

原来条数上限只写在 `HistoryService.MaxGenerationItems` 里，界面上完全看不出来，用户会以为
"记录怎么自己少了"。现在两处体现：

- 抽屉头部徽标：`15 / 30`（`HistoryCountText`，由 `HistoryService.MaxGenerationItems` 派生，
  上限改了文案跟着变）。
- 抽屉底部固定一行说明（带分隔线，不随列表滚动）：`最多保留 30 条，超出后自动删除最早的记录`
  （`HistoryLimitHint`）。

顺手把历史集合的通知集中了：`GenerationHistory.CollectionChanged` 统一刷新计数与空状态，
增删记录的地方不用再各自记得发 `OnPropertyChanged`（原来两处手写的通知已删除）。

### 第七轮：历史落盘挪到后台线程

生成完成后写历史的那一步（`bitmap.Save(path, ImageFormat.Png)`）原来是**同步跑在 UI 线程**上的：
`Generate()` → `GenerateAsync()`（全程没有 `ConfigureAwait(false)`，续体都回到 UI 线程）→
`FinishGeneration` → `HistoryService.AddGeneration`。PNG 编码是纯 CPU 活，这段时间窗口不能重绘、
不能响应点击。

实测（4K 3840×2560，含高频细节的位图，用 `DispatcherTimer` 测最大 tick 间隔）：

| | 最大 UI 停顿 | 流程总耗时 |
|---|---|---|
| 改动前（UI 线程同步保存） | **624 ms** | 603 ms |
| 改动后（`Task.Run` 后台保存） | **44 ms** | 602 ms |

改法（`ViewModels/AIRenderViewModel.cs`）：

- `PushGenerationHistory` → `SaveToHistoryAsync`，落盘走 `await Task.Run(() => HistoryService.AddGeneration(bitmap))`。
- `FinishGeneration` 改成 `async Task`，把**界面可见的反馈全部提前**（结果图、进度、状态、Toast），
  最后才 `await` 落盘 —— 否则结果图要等写盘完才出现，等于把停顿换成了延迟。
- 两个调用点改成 `await`。**不能 fire-and-forget**：位图在调用方的 `using` 作用域里，
  不 await 的话作用域会先 `Dispose` 掉它，编码中途被释放 → 崩溃或写出坏文件。
- 集合插入（`GenerationHistory.Insert`）留在 `await` 之后，也就是 UI 线程上 ——
  WPF 不允许在非 UI 线程改绑定中的 `ObservableCollection`。

副作用（有意保留）：`IsGenerating` 要等落盘完才归 false，所以生成按钮会多禁用约 0.6 秒。
状态栏这段时间显示「正在保存到历史…」，完成后改成「已保存到历史」。

顺带量到的存储数字（30 条上限）：PNG 单张 1K 3.6MB / 2K 7.7MB / 4K 15.3MB，
即 30 条最坏约 460MB、1K 档约 108MB。**没有**改成 JPEG：虽然编码只要 35ms、体积只有 1/4，
但历史图还会被「用作原图」「添加为参考图」「下载」复用，有损重编码会二次损失质量。

> ⚠️ 两份 `mockup-*.png` 是**最初的设计稿**，停留在这三轮调整之前（还带着渐变、空状态图标、
> 旧的图标）。当前的真实效果以 `implemented-window.png` 为准。

两张图都是**真实 WPF 渲染**（同一套 XAML 语法、同一个 `Microsoft YaHei UI` 字体、同样的
`RenderTargetBitmap` 管线），不是设计软件的示意图，所以图里的每个细节都能 1:1 落到
`Views/AIRenderWindow.xaml` 里。

## 与现状的差异

改动都集中在「样式层」，不动布局结构、不动 ViewModel 绑定。

### 1. 卡片有层次了（影响最大）

现状：白卡片 + 1px 灰描边，和背景几乎同亮度，整屏发平。

改版：
- 窗口底色改成极浅的纵向渐变 `#F8FAFD → #EAEFF8`
- 卡片圆角 12 → 15，描边降到 `#E8EDF6`
- 加柔光投影：`DropShadowEffect BlurRadius=26 ShadowDepth=4 Direction=270 Color=#16233A Opacity=0.10`

> 实现要点：投影**不要**直接加在卡片 Border 上——`Effect` 会把整棵子树先栅格化，卡片里的
> 中文小字会发虚。改版里用的是「空的阴影层 + 内容层」两层叠放（`CardHost` 模板），
> 文字仍然是矢量渲染。

### 2. 预览区从「一块灰底」变成「画布」

- 12px 细网格底纹（`DrawingBrush`，`TileMode=Tile`）
- 空状态：虚线圆角框 + 76px 圆角色块图标 + 主行动按钮（导入模型 / 上传图像）
- 有图时：左下角尺寸角标 `1280 × 1280 · 1.6MP`，右下角快捷操作（涂抹 / 清除）

### 3. 按钮分成三级

| 级别 | 用法 | 样式 |
|---|---|---|
| 主按钮 | 生成、（空状态）导入模型 | 实心强调色，`#3D83F7 → #1668F6` 纵向渐变，白字 SemiBold |
| 次按钮 | 卡片头部的导入 / 上传 / 下载 / 重新生成 | 34 高、9 圆角、白底 `#E1E7F1` 描边 |
| 幽灵按钮 | 涂抹修改、清除、从历史记录添加 | 无描边、`#F5F7FC` 底 |

主 CTA 从 200×36 放大到 186×52（圆角 13），禁用态改成平涂 `#E8EDF6` + `#A3AEBF` 文字——
现在的做法是给强调色整体打 45% 透明度，看着像"褪色的蓝按钮"，不像"不可用"。

### 3.5 圆角统一成一套刻度

现状一共有 **9 种**圆角取值：`4 / 6 / 7 / 8 / 10 / 11 / 12 / 14 / 999`。其中档位 chip 的
`SegmentButtonTemplate` 写死 7、图标按钮模板写死 8、卡片 12、生成按钮 10——同屏并存，
所以"模型设置"那排按钮看起来比别处方正。

改版按**元素尺寸分三档**，视觉圆度才一致（同样的 12px 圆角，放在 32px 高的 chip 上很圆，
放在 550px 宽的预览区上几乎看不出来）：

| 档位 | 圆角 | 元素 |
|---|---|---|
| 容器 | 16 | 卡片外壳 |
| 大块面 | 14 | 预览区、提示词输入框、参考图缩略图、主 CTA、虚线添加位 |
| 控件 | 12 | 头部按钮、图标按钮、模式按钮、尺寸/比例 chip |
| 胶囊 | 高度一半 | ≤28px 的小标签、计数徽标、图标色块 |

落地方式：把 `SegmentButtonTemplate` 和 `IconButtonTemplate` 里写死的 `CornerRadius="7"` /
`"8"` 改成 `{TemplateBinding Tag}`，然后所有按钮 Style 统一 `Tag="12"`——这样以后再调只改一处。

### 4. 卡片标题加了识别色

标题左侧一条 4×16 的圆角色条。输入类卡片（原始图像 / 参考图像 / 模型设置）统一用强调蓝，
输出类（生成结果）用紫色 `#7C5CFC`——只有一个次要色相，既区分了"输入/输出"，又不会花。

### 5. 排版分级

- 标题 15.5 SemiBold `#16202F`
- 说明文字 12 `#93A0B4`，行高 17（现在是 12.5 `#98A1AF`，行高偏紧）
- 空状态主标题 15.5 SemiBold `#33405A`，副标题 12.5 `#93A0B4`

### 6. 参考图卡片补了内容

右下两张卡在宽窗下等高，参考图卡原来只有一个小方块 + 一行字，底下大片空。改版补了
一条分隔线 + 一句说明（"参考图会作为图 2·3·4 一起送给模型"）+ 一个「从历史记录添加」入口。

### 7. 细节

- 右侧工具栏：图标 + 11.5px 文字，选中项用强调色淡底圆角块 + 强调色文字
- 底部加一条状态行：`标准模式 · 4K · 3:2 · 上次生成 18.4 秒`（左侧小圆点表示就绪）
- 提示词框：圆角 13 + 极浅投影，占位符 `#A8B0BD`，右下角字数，底部一行常用风格快捷 chip

## 落地建议

按「收益 / 风险」排序，前 3 项是纯样式改动，不动任何结构，可以先做：

1. `Card` 样式 + 窗口底色（第 1 节）—— 提升最明显，只改 `Style` 和 `Window.Background`
2. 按钮三级化（第 3 节）—— 只改按钮 Style，`CardButton` / `PrimaryButton` 已经是全局样式
3. 预览区画布 + 空状态（第 2 节）—— 只动两个预览 Border 内部
4. 标题识别色 / 排版分级（第 4、5 节）—— 纯 Setter
5. 参考图卡片补内容（第 6 节）—— 说明文字是纯样式；`从历史记录添加` 需要一个选择入口，
   VM 里 `AddHistoryAsReferenceCommand` 已存在但只接受具体条目，建议单独做
